# 실기기 한글 시험 안내 (P2-8 → P2-9, U-10)

> 시험장 `/dev/editor`에서 iPad와 갤럭시탭의 한글 입력이 PRD 9.3·16.3을 지키는지 10~20분 동안 확인한다. 실제 학생 글·이름은 쓰지 않는다(견본 글과 아무 글만).

## 1. Claude가 준비하는 것

1. 시험 빌드: `npm run build:devices` → `apps/web/dist-devices/`(`/dev/editor` 포함, 운영 빌드 `dist/`와 따로)
2. 서버 하나로 내주기: `npm run dev -- --devices` → 4461이 시험 빌드와 `/ws`를 함께 내준다(`DEV_DOCS_ENABLED=true`)
3. 잠깐 여는 HTTPS 주소: Cloudflare 빠른 터널 `cloudflared tunnel --url http://127.0.0.1:4461` → `https://<무작위>.trycloudflare.com`
   - 서버의 `PUBLIC_ORIGIN`을 이 주소로 맞춰 띄운다(보안 머리의 웹소켓 허용 주소).
   - 주소 뒤 `#dev=<비밀값>`이 있어야 글이 열린다. `#` 뒤는 서버로 가지 않고, 화면이 읽자마자 주소창에서 지운다.
   - 시험이 끝나면 터널과 서버를 끈다. 운영 서비스(4460)와 쌤유니버스 터널은 건드리지 않는다.
4. 사용자에게 보내는 것: 시험 주소 하나(학생 역할) + 이 안내서

## 2. 기기와 키보드 (하나씩 바꿔 가며)

| 기기 | 브라우저 | 키보드 |
|---|---|---|
| iPad | Safari | 화면 키보드(두벌식). 있으면 블루투스 키보드도 |
| 갤럭시탭 | Chrome | 삼성 키보드 **예측 켬**, **예측 끔**, **천지인** |
| 갤럭시탭 | Chrome | Gboard |

교사 쪽은 화면 안 **교사 봇 단추**가 대신한다(기기 하나로 충분). 두 번째 기기로 같은 주소에 `?role=teacher`를 붙여 열면 사람이 직접 고쳐 볼 수도 있다(선택).

## 3. 할 일

화면 아래 **실기기 확인 체크리스트(15항목)**를 펼쳐 위에서부터 해 보고, 된 것에 체크한다. 체크는 그 기기에만 남는다.

추가로 볼 것 두 가지:
- **제목 칸에 커서를 두고** 교사 봇 1·2번을 누른 뒤 본문을 다시 눌렀을 때, 본문 커서가 원래 자리에 있고 글자가 한꺼번에 지워지지 않는다(P2-3c에서 고친 부분).
- 화면 키보드가 올라와도 **아래 바(저장 상태·되돌리기)**와 쓰던 줄이 가려지지 않는다(PRD 16.5).

이상한 일이 생기면: 그 자리에서 멈추고 무엇을 치던 중이었는지 한 줄 적은 뒤 **진단 기록 내려받기**를 누른다.

## 4. 기기마다 끝나면

1. **진단 기록 내려받기** → JSON 파일 하나가 받아진다(입력 이벤트 순서·시각과 그때 칸에 있던 글자·커서 위치. 그래서 시험 문장과 아무 글만 친다. 서버로는 가지 않는다).
   - iPad: 파일 앱 → 다운로드 → AirDrop으로 맥에 보낸다.
   - 갤럭시탭: 내 파일 → 다운로드 → Quick Share·카카오톡 나에게 보내기 등으로 맥에 옮긴다.
2. 맥의 `writeessay/.local/device-traces/`에 넣는다(폴더가 없으면 만든다). 파일 이름 앞에 기기·키보드를 붙이면 좋다(`ipad-safari-…json`, `tab-samsung-predict-on-…json`).
3. 체크하지 못한 항목 번호와 한 줄 메모를 Claude에게 보낸다.

## 5. 결과를 보고 Claude가 하는 일

- 진단 기록을 `tests/fixtures/ime-traces/`의 재생 시험 자료로 옮긴다(PLAN §10.3, Safari 상태를 재현하려면 칸의 글자·커서가 필요해 그대로 둔다. 시험 문장만 들어 있다).
- 실패 항목은 원인을 찾아 고친 뒤 같은 항목만 다시 부탁드린다.
- 전부 통과하면 PRD 16.3 실기기 항목을 체크하고 P2를 닫는다. 같은 문단 동시 편집에서 막는 문제가 끝내 남으면 PRD 9.3 차선책(같은 편집기 포트 뒤 CodeMirror 6)으로 간다.
