## 만들 것 (`packages/core/src/domain/`, 순수 함수, 시각은 인자)
1. `aiQuota.ts`: KST 하루 키(`TIMEZONE`, 기존 `clock.ts`의 `dayKey` 활용), 한도 판단 순서(PLAN §8.2: 같은 commandId → 버튼별 쿨다운 `AI_COOLDOWN_SEC` → 참가자 하루 `AI_DAILY_PER_PARTICIPANT` → 방 하루 `AI_DAILY_PER_ROOM` → 전체 `AI_DAILY_GLOBAL`(개인 모드는 `AI_DAILY_PERSONAL_GLOBAL`))을 "지금 쓴 수 → 허용/거절 코드(`E_AI_COOLDOWN`·`E_AI_LIMIT`)·남은 쿨다운 초"로. 기기 쪽 칩 상태에도 쓸 수 있게 `cooldownLeftSec(lastAt, now, config)`.
2. `timer.ts`: 타이머 상태 기계(IDLE·RUNNING·PAUSED: 시작·멈춤·다시·취소, 남은 시간·끝 시각 계산), 알림 시각 목록(`alerts`는 "끝나기 n분 전", PRD F-19: 5분 전·1분 전·끝), 재시작 뒤 복원(저장된 값 + 지금 시각 → 지금 상태와 아직 안 보낸 알림). `TIMER_MAX_MIN` 검사.
3. `resume.ts`: 이어 쓰기 요청 상태 전이(PENDING → APPROVED·REJECTED·CANCELLED만, 끝난 것은 그대로), 같은 기기·같은 별명의 대기 요청 재사용 판단, 긴 조회 대기 시간(`RESUME_LONGPOLL_SEC`) 자르기, 안내 시간 `RESUME_WAIT_HINT_MIN`.
4. 단위 시험(P4-2): 파일마다 `*.test.ts`. KST 자정 경계(23:59:59 → 00:00:00), 쿨다운 경계, 한도 정확히 N번째, 타이머 멈춤·다시 뒤 남은 시간, 알림이 과거로 가는 경우, 상태 전이 표 전부. 성질 시험(fast-check)으로 타이머 멈춤·다시를 임의 순서로 해도 남은 시간이 음수가 되지 않음.
5. `index.ts`에 내보내기 줄을 더한다.
