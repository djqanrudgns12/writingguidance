## 할 일
검토의 P0 2건·P1 6건·P2 3건을 모두 고친다. 검토의 "고칠 방법"을 따르되 더 나은 방법이 있으면 이유를 보고한다. 특히:
- P0 메모: 마운트·렌더링 때 `memo.set`을 절대 하지 않는다(읽기는 없으면 ""). 처음 글자를 칠 때만 만든다. 기존 메모를 덮지 않음을 시험으로 보인다.
- P0 되돌리기: 반영 문이 열릴 때(조합 아님 + 멈춤 + 음절 경계)만 실행. `preventDefault`는 동기로 유지. 보류 원격이 있으면 flush 먼저, 그다음 undo를 따로.
- P1 `setReadOnly`·`select`·`applyAppEdit`: `whenIdle` 대신 반영 문 열림(`decide().open`)을 기다리고 깨어난 순간 다시 확인. 필요하면 `Gate`에 `whenOpen()`을 더한다.
- P1 조합 고착: `isComposing:false` 입력(229·'Process' 제외)이나 고착 판정 뒤 `composing`을 내린다.
- P1 `selectionchange` 에코: 시간 문턱 대신 기대 선택값 비교. 선택이 이미 같으면 `setSelectionRange`를 부르지 않는다.
- P1 줄바꿈 정규화: `<input>`(제목)과 `<textarea>`의 값 모양 차이로 `lastRendered`와 `el.value`가 어긋나지 않게. 제목의 `\n`·모든 `\r`은 기록 단계와 서버 적용 전 검사에서 막는다.
- P1 awareness: zod로 검증하고 변환을 try/catch로 감싸, 나쁜 값 하나로 flush가 멈추거나 `viewDoc.share`가 늘지 않게.
- P1 거울 층: 글자 크기·글꼴 로드 뒤 다시 맞추기(`EditorBinding.syncLayout()` 추가), 커서가 줄바꿈을 바꾸지 않게, 스크롤바 폭·탄성 스크롤.
- P2: 되돌리기 묶음을 칸 전환·앱 편집 앞뒤에서 끊기(`stopCapturing`), 선택 범위가 있을 때 음절 판정, `EditorBinding.bindMemo(id, el)`.
