## 만들 것 (`tests/e2e/`)
PLAN §10.5 표의 파일: `student-join`, `ai-panels`, `realtime`, `offline`, `rewind`, `teacher`, `layout`, `retention`, `design`(`ime`는 있음). 표의 항목을 가능한 만큼 덮는다. 우선순위: student-join → realtime → teacher → offline → ai-panels → rewind → layout → design → retention.
- 브라우저는 **Chromium만**(WebKit 내려받기 금지, 설정에 WebKit 프로젝트를 더하지 않음 — 나중 일). 폭은 360·1280 두 가지를 기본으로, layout만 360·768·1024·1280.
- 시험 서버 환경: 설정의 `webServer.env`에 PLAN §10.5대로 `SNAPSHOT_INTERVAL_SEC=1`, `ROOM_TTL_MINUTES_OVERRIDE=2`, `AI_PROVIDER=fake`, 시작 코드(`TEACHER_START_CODE`, 시험용 숫자 8자리)를 더한다(`playwright.config.ts`·`tests/e2e/constants.ts` 고쳐도 됨). 타이머 알림 간격 축소가 설정에 없으면 그 항목은 건너뛰고 보고.
- 교사·학생은 서로 다른 브라우저 컨텍스트로. 방은 화면(T1)으로 만들거나, 빠르게 할 때는 REST(시험 도구처럼)로.
- 오프라인은 `context.setOffline`, 서버 재시작은 하지 않는다(webServer 하나라 어렵다: 건너뛰고 보고).
- 고정 `waitForTimeout` 대신 조건 기다림. 같은 시험을 3번 돌려 흔들리지 않게.
- 앱 결함을 찾으면 시험을 약하게 만들지 말고 실패한 채 두고(`test.fail`로 표시하지 말 것) 보고한다. 시험 쪽 문제면 고친다.
## 실행
먼저 `npm run build:devices`(시험 서버가 `dist-devices`를 내준다. 앱 코드가 바뀌면 다시 빌드), 그다음 `npx playwright test --workers=1`. 자원 보호 장치는 이번 작업에서 쓰지 않아도 된다(사용자가 이번 확인 단계는 허용). 3회 연속 실행 결과를 보고.
