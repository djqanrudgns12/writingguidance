## 문제
`editor.property.test.ts`가 6번 중 1번꼴로 실패한다. 잡은 반례(그대로 재현):
```
{ seed: -2059837136, path: "8:1:2:2:2:2:2:2:2:1:1:4:4:1:4:3:12:10:2:3:1:3:2:1:1:4:1:1:2:3:1:7:3:3:4:4:4:1:1:2:3:2:2:3:3:3:2:1:2", endOnFailure: true }
줄인 반례 일부: 학생(actor 0)이 커서를 0으로 옮김 → '한'→'하나' 조합 → 그 도중 다른 기기(actor 1)가 ' '를 동시에 넣음 → 3000ms 진행 → 단언 "expected 0 to be greater than or equal to 1"(학생 커서가 0)
```
다른 실행에서는 "expected ' ' to be '가'"(학생 커서 앞 글자가 자기가 친 글자가 아님)로도 실패했다.

## 할 일
1. `fc.assert(..., { seed, path, endOnFailure: true })`로 재현하고, 원인이 **편집기 결함**인지 **시험(하네스·단언·생성기) 결함**인지 가린다. 근거(재현 단계별 입력칸 값·선택·viewDoc·netDoc)를 보고한다.
2. 편집기 결함이면 `apps/web/src/adapters/editor/*.ts`를 고친다(PRD 9.3·ADR-054 규칙은 그대로). 시험 결함이면 시험을 고치되 **기대값을 약하게 하지 않는다**: 같은 자리 동시 입력에서 커서가 어디 있어야 맞는지(Yjs 상대 위치 assoc -1 규칙)를 근거로 정확한 단언으로 바꾼다.
3. 고친 뒤 성질 시험을 **최소 20번** 연속 실행해 모두 통과함을 보인다(seed를 바꿔 가며).
