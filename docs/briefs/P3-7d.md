상황(Claude가 운영 빌드로 확인, 2026-11-11): 경로별 지연 불러오기로 첫 화면 JS는 예산 안(gzip 약 213KB/250KB). 그런데 `node tools/checks/bundle.mjs`가 **첫 화면 그림 339,917B > 81,920B**로 실패한다. 원인: `apps/web/src/ui/art/index.ts`가 그림 24개 주소를 한 모듈에 모아 두고, 홈이 쓰는 부품(`Gulbeot`·`PaperCard` 등)이 그것을 가져와 그림 주소 묶음(`art-*.js`)이 첫 묶음에 정적으로 딸려 온다. 검사는 첫 묶음이 가리키는 그림을 모두 첫 화면 그림으로 센다(검사 기준은 바꾸지 않는다).
## 할 일
- 첫 묶음(학생 홈 `/`)이 **홈이 실제로 그리는 그림만** 가리키게 나눈다: 홈 그림(`home-book`), 글벗 기본 얼굴(`gulbeot-face`), 홈 카드 테두리 SVG, 종이 결. 나머지(글벗 표정 5개, 장면 그림 `waiting-letter`·`closed-door`·`empty-desks`·`offline-umbrella`·`submit-stamp`, 도장·빈 화면 테두리)는 쓰는 부품이 그릴 때 동적 import로 주소를 받는다(그림 자체도 원래 화면에 보일 때 받으니 사용자는 차이를 못 느낀다. 주소를 받기 전에는 같은 크기 빈 자리를 두어 배치가 흔들리지 않게).
- 방법은 자유(예: `art/index.ts`를 묶음별 모듈로 나누고 `Gulbeot`은 `face`만 정적, 나머지는 `import()`). 공개 props·모양은 바꾸지 않는다. `art/index.ts`의 기존 내보내기를 쓰는 곳(`grep -rn "ui/art" apps/web/src`)이 깨지지 않게.
- 확인: `npm run build -w @geulbang/web && node tools/checks/bundle.mjs`가 통과(종료 0). `npx tsc -p apps/web`, `npx vitest run --project web --maxWorkers=1 src/ui`, `node --test tools/checks/checks.test.mjs`. 빌드는 가벼워 resource-guard 없이 돌려도 된다(사용자 허용, 이번 확인 단계).
## 고칠 수 있는 파일
`apps/web/src/ui/components/**`, `apps/web/src/ui/art/**`(그림 파일 자체는 그대로, `index.ts`와 새 색인 모듈). 그 밖 금지(`ui/screens/**`·`app/**`는 필요하면 보고, `tools/checks/**` 기준 바꾸기 금지).
