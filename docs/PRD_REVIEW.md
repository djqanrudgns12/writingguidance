## 0. 한 줄 판정

기능 범위와 원칙은 탄탄하다. 다만 **(1) 한국 지연 가정, (2) 글 1개 = 객체 1개 구조의 무료 한도, (3) 한글 IME와 동시 편집, (4) 현행 LLM이 온도를 받지 않는 점** 네 가지는 그대로 구현하면 첫 수업에서 문제가 된다. 넷 다 구조를 조금 바꾸면 PRD의 `[고정]` 요구를 하나도 건드리지 않고 풀린다.

| R2 | Cloudflare 무료가 한국에서 빠르다 | 위 C7. | 실시간은 목표 안. 첫 화면은 PWA·번들 다이어트. 앞단 선택 U-02 |
| R3 | 21명 규모면 무료 한도 여유가 크다 | 글마다 객체를 깨우는 구조에서는 실행 시간(GB-s)과 요청 수를 수업 1~2번에 크게 쓴다. | 수업방 단위 객체, 휴면(Hibernation), 하트비트 자동 응답, 보내기 묶음. 계산은 PLAN §2.6 |

## 4. 단순화한 것과 하지 않은 것

- **한 것**: DocObject·DirectoryObject 제거(수업방 객체 + D1), 맞춤법 위치를 모델에게 받지 않기, 온도 설정 제거, 첫 입장 화면 하나 줄이기.
- **Antigravity가 제안했지만 따르지 않은 것과 이유**
  - "개인 모드를 v1에서 아예 빼기": PRD가 이미 v1.1이다. 데이터 모델과 객체만 v1에 열어 두고 화면은 v1.1에 넣는다(나중에 구조를 바꾸지 않으려고).
  - "스냅샷을 2~3분 간격, 30~50개로 줄이기": 수업방 객체 안에서 글자 스냅샷으로 저장하면 30초 간격도 수업 1회에 약 1,700행이라 한도에 부담이 없다. PRD 값 유지.
  - "이전으로 묶음 단위 설정 빼기": F-22(SHOULD) 설정 화면에 한 줄이라 비용이 작다. 유지.
  - "Suno 복사를 학생 메뉴에서 빼기": F-12가 MUST다. 학생 메뉴는 두고 교사 서랍에 추가만 한다(G30).
- Antigravity가 추천한 모델(`Claude 3.5 Haiku`, `gpt-4o-mini`)은 지난 세대다. 현행 모델로 다시 정리했다(U-01).
