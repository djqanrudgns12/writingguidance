# 결정 기록 (에이전트 판단)

> PRD 0.1에 따라 `[추천]` 항목을 바꾸거나, PRD가 비워 둔 부분을 에이전트가 정한 기록이다.
> `[고정]` 항목은 바꾸지 않았다. `[고정]`끼리 부딪쳐 해석이 필요한 것(ADR-017의 "주요 버튼 하나")은 임시 해석으로 진행하되 `docs/USER_DECISIONS.md` U-16으로 확인을 받는다. 그 밖에 사용자 결정이 필요한 것도 USER_DECISIONS(U-xx)에 있다.
> 형식: **결정 / 이유 / 버린 대안 / 되돌리기**. 사실 근거의 출처는 각 항목 끝에 적었다.
> 상태: `확정` = 이대로 구현 · `관문` = 정한 시점에 실측으로 확인하고 필요하면 바꿈

## ADR-001 · 런타임: Cloudflare Workers + Durable Objects + D1, 앞단 중립  — **v2에서 대체됨 → ADR-037**

- **결정**: Worker 1개가 정적 앱, `/api`(Hono), 웹소켓 입구를 모두 맡는다. 실시간·저장은 Durable Object(SQLite), 전역 색인은 D1. 접속 주소와 앞단(CloudFront 여부)은 앱 코드와 무관하게 바꿀 수 있게 둔다.
- **이유**: 무료 플랜에서 Durable Objects(SQLite 백엔드만)와 D1을 쓸 수 있고, 객체 알람으로 30일 삭제를 크론 없이 할 수 있다. PRD 11장 조건(무료, 가볍게, 검증된 플랫폼)에 맞는다.
- **버린 대안**: 맥미니 자체 호스팅(U-03 참조), Supabase·Firebase(PRD 11.4).
- **되돌리기**: `RealtimePort`·`DocStorePort` 뒤에 플랫폼 코드를 둔다. Postgres + Hocuspocus로 옮길 때 서버 어댑터만 새로 쓴다.
- **출처**: developers.cloudflare.com/durable-objects/platform/pricing/ (무료: 요청 10만/일, 실행 13,000 GB-s/일, 읽은 행 500만/일, 쓴 행 10만/일, 저장 5GB, 00:00 UTC 초기화), developers.cloudflare.com/d1/platform/pricing/ (2026-09-01부터 무료 한도 초과 시 쿼리 오류).

## ADR-002 · 수업방 1개 = Durable Object 1개  — **v2에서 대체됨 → ADR-037**

- **결정**: PRD 9.1의 `DocObject`(글마다 객체)를 없애고, `RoomObject` 하나가 그 방의 참가자·기기·모든 글의 Yjs 상태·스냅샷·알림·타이머·이어 쓰기 요청·AI 사용량을 가진다.
- **이유**
  1. **실행 시간 한도**: 연결이 열려 있는 객체는 128MB 전체로 시간이 계산된다. 40분 수업에 객체 1개면 약 300 GB-s, 글마다 객체면 21개 × 300 = 6,300 GB-s라 하루 2번 수업이면 무료 13,000 GB-s를 거의 다 쓴다.
  2. **요청 수**: 글 객체가 1초마다 수업방 객체에 요약을 보내면 그 자체로 수업 1회에 약 5만 건이다. 한 객체 안이면 0건.
  3. **기능 단순화**: 모두 내려받기(G4), 대시보드 요약, 수업방 전체 삭제가 한 객체 안에서 끝난다.
- **버린 대안**: PRD 9.1 그대로(위 한도 문제), 객체 하나에 Yjs 문서 하나만 두는 y-partyserver 방식(ADR-004).
- **한계와 대응**: 객체 하나의 처리량은 초당 약 1,000건(연성 한도)이라 30명 규모에서 여유가 크다. 객체당 저장은 문서가 1GB/10GB로 엇갈려 **1GB로 보고 설계**한다(글 50편 × 스냅샷 300개 × 6KB ≈ 90MB).
- **출처**: 위 pricing 문서("accept()로 연결 중이면 연결 내내 과금, 휴면 중에는 과금 없음"), developers.cloudflare.com/durable-objects/platform/limits/.

## ADR-003 · 전역 색인은 D1  — **v2에서 대체됨 → ADR-039**

- **결정**: `DirectoryObject` 대신 D1 테이블로 "입장 코드 → 방", "PIN HMAC → 방", 전역 AI 하루 사용량, 속도 제한 칸을 둔다.
- **이유**: 유일성(`UNIQUE`)을 DB가 보장하고, 쌤유니버스 Postgres로 옮길 때 SQL이 거의 그대로다. `wrangler d1 migrations`가 번호 붙은 SQL 파일 방식이라 쌤유니버스 `infra/migrations/NNNN_*.sql` 규칙과 같다. 쓰는 양은 하루 수백 행이라 무료 한도(쓴 행 10만/일)와 거리가 멀다.
- **버린 대안**: 전역 객체 1개(PRD 안). 같은 일을 하지만 마이그레이션 도구와 조회 도구가 없다.
- PRD 11.5가 이 대안을 미리 허용했다.

## ADR-004 · Yjs 동기화는 자체 프로토콜  — **v2에서 대체됨 → ADR-038**

- **결정**: `y-protocols`(sync·awareness)와 `lib0` 인코딩으로 **연결 하나에 여러 문서를 싣는** 작은 프로토콜을 직접 만든다(PLAN §4). y-partyserver와 partysocket은 쓰지 않는다.
- **이유**
  1. y-partyserver는 "객체 1개 = 문서 1개" 구조라 ADR-002와 맞지 않는다.
  2. 휴면(Hibernation)이 기본값 꺼짐이고, 패키지가 2026-04-24 이후 새 판이 없으며 변경이 사실상 관리자 1명에 몰려 있다. `@cloudflare/workers-types`를 v4로만 허용하는 의존성 충돌 가능성도 있다.
  3. 읽기 전용(제출·닫힘) 거부, 보내기 묶음(ADR-020), 조합 중 반영 보류(ADR-006), 첫 메시지 인증(ADR-019)을 우리 규칙대로 넣어야 한다.
- **버린 대안**: y-partyserver(위 이유), Hocuspocus(Node 서버라 Workers에서 못 돈다. 나중에 Postgres로 옮길 때의 후보로 남긴다).
- **비용**: 서버 약 400줄, 클라이언트 약 300줄. 단위·통합 시험으로 덮는다(PLAN §10).
- **출처**: registry.npmjs.org/y-partyserver (2.2.0, 2026-04-24), github.com/cloudflare/partykit `packages/partyserver/src/index.ts`(`hibernate: false` 기본값).

## ADR-005 · 편집기: `textarea` + `Y.Text` 바인딩 (관문)  — v2에서 보강·변경 → ADR-040

- **결정**: 쓰기 칸은 브라우저 기본 `<textarea>`이고, 우리가 만든 바인딩이 `Y.Text`와 맞춘다. Tiptap·ProseMirror는 쓰지 않는다. 선생님 커서·맞춤법 형광 표시는 입력칸 뒤에 같은 글꼴의 거울 층을 두고 그린다.
- **이유**
  1. **한글 입력 안정성(16.4)**: 입력과 조합을 브라우저가 직접 처리하므로 iPad Safari·삼성 키보드·Gboard에서 가장 덜 깨진다. 우리는 "언제 화면 값을 바꿔도 되는가"만 다루면 된다(ADR-006).
  2. **PRD와 맞음**: 서식이 없고(F-06) 글자 위치가 곧 문자열 위치라 맞춤법 위치(F-08)·Suno 변환(F-12)·내려받기가 단순하다(Antigravity 지적 C10).
  3. **가벼움**: ProseMirror+Tiptap+y-prosemirror 묶음(압축 약 100KB, 추정)이 빠진다.
- **버린 대안**: Tiptap + Collaboration(PRD 안). 커서 표시·장식이 기본 제공되는 장점이 있지만, 한글 조합 문제가 생기면 ProseMirror 내부라 우리가 고치기 어렵다.
- **관문**: M2 끝 실기기 확인(U-10). 만약 기본 입력칸에서 거울 층 커서가 실기기에서 크게 어긋나면, 같은 `EditorPort` 뒤에서 Tiptap 어댑터로 바꾼다(학생·교사 화면 코드는 그대로).
- **근거(2026-11-10 조사)**
  - Tiptap v3(3.33.0)의 Collaboration은 `@tiptap/y-tiptap`을 쓰는데, 원격 변경이 오면 바뀐 최상위 문단 노드를 통째로 바꾼다(`replaceChangedChildren`). 학생이 조합 중인 문단을 교사가 고치면 조합이 끊길 가능성이 크다.
  - Tiptap #5250(협업 커서를 켠 채 한글 조합 중 다른 곳을 누르면 글자가 사라짐)이 열려 있다. y-prosemirror의 조합 처리 PR #107은 병합되지 않고 닫혔다.
  - `y-textarea` 1.0.2는 조합을 처리하지 않고 원격 변경 때 값을 통째로 덮어써서 쓸 수 없다. 그래서 바인딩을 직접 만든다.
  - 사용자별 되돌리기는 Yjs `UndoManager`의 `trackedOrigins`로 Tiptap과 같은 방식(내 기기의 로컬 변경만)으로 된다.

## ADR-006 · 한글 조합 중에는 원격 변경 반영을 미룬다 (관문)  — v2에서 보강·변경 → ADR-040

- **결정**: 바인딩은 "마지막으로 그린 글"을 기억하고, 입력이 생기면 그 글과 지금 입력칸 값의 차이를 `Y.Text` 변경으로 만든다. 다른 사람(교사·다른 기기)의 변경은 **조합 중이거나 마지막 입력 후 `IME_SETTLE_MS`(300ms)가 지나지 않았으면** 받은 Yjs 업데이트를 줄에 세워 두었다가, 조합이 끝난 뒤 적용하고 다시 그린다. 커서 위치는 `Y.RelativePosition`으로 옮긴다.
- **이유**: 조합 중에 입력칸 값을 바꾸면 Safari는 조합을 끊는다. CRDT라 받은 업데이트를 늦게 적용해도 결과가 같으므로, 미루는 것이 가장 안전하다. 조합 이벤트가 불규칙한 안드로이드 키보드도 "입력 후 300ms" 조건으로 덮는다.
- **영향**: 학생이 쉬지 않고 쓰는 동안 학생 화면에 교사 변경이 최대 수백 ms 늦게 보인다. 교사 화면으로 가는 쪽(학생→교사)은 늦어지지 않는다.

## ADR-007 · 스냅샷은 글자 스냅샷, 복원은 차이만 적용

- **결정**: 시간 되감기 스냅샷은 Yjs 스냅샷(`gc: false` 필요)이 아니라 **본문·제목 글자**를 저장한다. 복원은 스냅샷 글과 현재 글의 차이만 `Y.Text`에 한 번의 변경으로 적용하고 `restore` 스냅샷을 남긴다.
- **이유**: Yjs 스냅샷은 문서 가비지 컬렉션을 꺼야 해서 지운 글자가 계속 쌓인다. 서식 없는 글이라 글자 스냅샷으로 충분하고 크기가 작다(수 KB). 차이만 적용하면 복원 순간 다른 사람이 쓰던 커서가 튀지 않는다.
- **정리 규칙(C5)**: 300개를 넘으면 `auto`만 솎는다. 최근 10분은 모두, 1시간까지는 1분에 1개, 그 뒤는 5분에 1개. `submit`·`ai`·`teacher`·`restore`는 지우지 않는다.
- **스냅샷 시점**: 서버 저장 시점에 글이 바뀌었고 마지막 `auto`가 30초 이전이면 `auto`. 제출·AI 요청·교사가 그 글에 처음 입력할 때·복원 직전에 이벤트 스냅샷.
- **기기 만료(G20)**: 기기 기억에도 만료 시각을 저장해, 앱을 열 때 인터넷 없이도 만료된 방의 기기 사본(IndexedDB)을 지운다.

## ADR-008 · AI 호출은 수업방 객체 안에서  — **v2에서 대체됨 → ADR-037**

- **결정**: `POST /api/rooms/:roomId/ai`는 Worker가 인증 정보만 붙여 `RoomObject`로 넘긴다. 객체가 한도 확인 → `ai` 스냅샷 → 모델 호출 → 사용량 기록을 한 번에 한다. 맞춤법·피드백·다음 방향은 스트리밍 없이 구조화 JSON, 다듬은 글은 **제공사 스트림 바이트를 그대로** 브라우저로 흘려보내고 브라우저가 글자 조각만 꺼낸다.
- **이유**: 한도 집계가 한 곳에서 원자적으로 되고, 스냅샷을 같은 객체가 남긴다. Worker 무료 CPU는 요청당 10ms라 스트림 조각을 하나하나 풀면 넘칠 수 있는데(추정), 바이트를 그대로 넘기면 파싱 CPU가 거의 없다. LLM 응답을 기다리는 시간은 CPU에 들어가지 않는다.
- **영향**: 다듬은 글의 토큰 수는 글자 수로 추정해 기록한다(PRD 6.6 메타데이터만 남기는 원칙은 그대로).
- **출처**: developers.cloudflare.com/workers/platform/limits/ ("`fetch()` 응답 대기는 CPU 시간에 들어가지 않음").

## ADR-009 · AI 계층: `AiPort` + 제공사 공식 SDK 어댑터

- **결정**: PRD 6.4의 Vercel AI SDK 대신, 우리 `AiPort` 인터페이스(버튼·입력·스키마 → 결과/스트림) 아래에 제공사별 어댑터를 둔다. Anthropic은 공식 `@anthropic-ai/sdk`, OpenAI를 고르면 공식 `openai` SDK. 모델 이름·추론 강도는 설정값.
- **이유**: 현행 Claude 5.5 계열은 요청 모양이 많이 바뀌었다(온도 거절, 추론 끄기 규칙, 추론 강도 `output_config.effort`, 구조화 출력 `output_config.format`, `refusal` 중단 사유). 공통 계층은 이런 새 매개변수를 늦게 따라올 수 있다. 공식 SDK의 `asResponse()`로 원본 스트림을 그대로 넘길 수 있어 ADR-008과도 맞는다. 제공사를 바꿔도 앱 코드가 그대로라는 PRD 목적은 `AiPort`로 지킨다.
- **버린 대안**: Vercel AI SDK `ai` 7.x (Workers에서 동작하고 예전 멈춤 버그도 고쳐졌지만, 위 이유로 우리 포트가 더 단순하다).
- **세부**: SDK 자체 재시도는 끄고(`maxRetries: 0`) PRD 6.5 재시도 규칙을 우리가 한다. Sonnet 5.5로 다듬은 글을 돌릴 때는 거절 대비 서버 측 대체(`fallbacks: "default"`)를 켠다. Haiku 5.5에는 서버 측 대체가 없어 `E_AI_REFUSED` 문구로 처리한다.

## ADR-010 · 온도 설정 제거

- **결정**: `temperature` 설정을 없애고 버튼별 `AI_EFFORT_*`(`low`/`medium`/`high`)와 `AI_THINKING_*`(`off`/`adaptive`)를 둔다. "다음 방향"의 다양성은 프롬프트("서로 다른 방향 3개, 겹치지 않게")로 만든다.
- **이유**: Claude 5.5 계열은 기본값이 아닌 `temperature`를 400으로 거절하고, API 버전 2026-10-21부터 모든 모델이 거절한다. OpenAI 추론 모델도 온도를 고정한다.
- **초기값**(M5 평가로 확정): 맞춤법 `low`/`off`, 피드백 `low`/`adaptive`, 다음 방향 `medium`/`adaptive`, 다듬은 글 `low`/`off`.

## ADR-011 · 맞춤법 위치는 화면이 찾는다

- **결정**: 응답 스키마에서 `start`를 빼고 `context`(틀린 표현 앞뒤 각 6자 이내)를 넣는다. 화면은 요청 당시 글과 지금 글의 차이로 예상 위치를 옮긴 뒤, `context`가 맞는 `original`을 찾고, 여러 개면 예상 위치에 가까운 것을 고른다. 못 찾으면 목록에는 두고 `위치 보기`만 숨긴다(PRD 6.3 규칙 유지).
- **추가 걸러내기**: `original`이 본문에 없거나, `original === suggestion`이거나, 같은 위치가 겹치는 항목은 버린다. 최대 30개.

## ADR-012 · 스타일: CSS Modules + `tokens.css`

- **결정**: Tailwind를 쓰지 않는다. 디자인 토큰은 `tokens.css`의 CSS 변수, 컴포넌트 스타일은 CSS Modules(Vite 기본 지원). 화면 CSS에 색 코드를 직접 쓰지 않는다.
- **이유**: 쌤유니버스가 Tailwind 없이 같은 방식(`apps/web/src/tokens.css`, `docs/design/UI_SYSTEM.md` "화면 CSS에 hex 금지")이다. 나중에 쌤유니버스에 붙일 때 그대로 옮길 수 있고, 의존성이 하나 줄어든다.
- **토큰 이름**: PRD 8장 이름을 쓰되, 쌤유니버스 이름과의 대응표를 `tokens.css` 머리에 둔다(`--bg`↔`--paper`, `--text`↔`--ink`, `--primary`↔`--accent`, 모서리 `--r-*`). 글꼴 토큰은 PRD `[고정]`대로 `--font-sans` 하나.

## ADR-013 · 헤드리스 부품 라이브러리: Base UI

- **결정**: `@base-ui/react`(MUI Base UI v1)로 Dialog·Popover·Menu·Select·Switch·Slider·Checkbox·Toast를 만들고 전부 우리 토큰으로 꾸민다. 브라우저 기본 `select`는 쓰지 않는다(PRD 8.2).
- **이유**: 2025-12에 1.0 안정판이 나왔고 매달 새 판이 나온다(조사 시점 1.9.0). 패키지 하나에 필요한 부품이 다 있다. Radix(`radix-ui` 1.8.1)도 활발하지만 열린 이슈가 많고, 쌤유니버스도 아직 어느 쪽도 설치하지 않아 맞출 기준이 없다.
- **되돌리기**: 부품은 `ui/components/` 안에서만 Base UI를 가져온다. 화면 코드는 우리 부품만 쓰므로 Radix로 바꿔도 화면은 그대로다.
- **출처**: github.com/mui/base-ui (1.9.0, 2026-10-09), github.com/radix-ui/primitives (1.8.1, 2026-10-12).

## ADR-014 · 아이콘

- **결정**: 쌤유니버스처럼 `@phosphor-icons/core`의 SVG에서 쓰는 아이콘만 골라 `icons.generated.tsx`를 만드는 스크립트를 둔다. 굵기는 **Duotone 하나**. 화면은 `<Icon name="...">`만 쓴다.

## ADR-015 · 도구·버전

## ADR-016 · 입장 코드: 숫자 6자리

- **결정**: 입장 코드는 숫자 6자리(100000~999999), 입력칸은 숫자 키패드(`inputmode="numeric"`).
- **이유**: 영문이 섞이면 태블릿에서 한/영 전환이 필요해 초3이 막힌다. 숫자만 쓰면 헷갈리는 글자 문제(PRD F-02)도 사라진다. 90만 가지라 활성 방 수십 개에서 겹칠 일이 거의 없다. 조회 제한은 기기 ID 기준 분당 30회, IP 기준은 학교 공유 IP를 고려해 분당 600회로 높게 둔다(ADR-018과 같은 이유).
- **영향**: 주소는 `https://{도메인}/{6자리}`. 예약 경로(`t`, `p`, `privacy`, `api`, `assets`)는 숫자가 아니라 충돌하지 않는다.

## ADR-017 · 첫 입장 화면 줄이기, "주요 버튼 하나" 해석 (3번은 U-16 확인 대기)  — v2에서 보강·변경 → ADR-042

- **결정**
  1. QR로 처음 들어오면 **수업 카드와 동의를 한 화면**에 둔다(카드 위, 짧은 안내·체크·`시작하기` 아래). 이미 동의했으면 카드만 보이고 바로 다음.
  2. `기타 문구`의 용도 카드와 `직접 입력`은 글 종류 화면 안에서 펼친다.
  3. "주요 버튼 하나"는 **채운 주요색 버튼이 화면당 1개**라는 뜻으로 고정하고, 나머지는 테두리·칩 모양의 보조 버튼으로 한다. 쓰기 화면의 주요색은 `제출`, AI 버튼 4개는 칩.
- **결과**: QR → 쓰기까지 3화면(카드+동의 → 별명 → 글 종류). 16.1의 "4화면 이내"를 지킨다.

## ADR-018 · PIN 실패 제한  — v2에서 보강·변경 → ADR-039

- **결정**: 실패를 세 칸으로 센다. ① 기기 ID 기준 5회 → 10분 잠금(PRD 값) ② IP 기준 30회/10분 → 그 IP의 PIN 입력만 10분 잠금 ③ 전역 100회/10분 → 모든 PIN 응답에 2초 지연. 수업방 만들기의 "이미 쓰이는 PIN" 확인도 같은 칸으로 센다(PIN 존재 여부를 캐내는 길이기 때문).
- **이유**: 학교는 공인 IP 하나를 함께 쓰므로 IP만으로 세면 학생 장난 한 번에 교사가 막힌다(Antigravity 지적). 기기 ID는 지울 수 있으니 IP·전역 칸이 뒤를 받친다.
- **저장**: D1 `rate_buckets`(키는 기기 ID·IP의 HMAC, 10분 창). IP 원문은 저장하지 않는다.

## ADR-019 · 자격 증명  — v2에서 보강·변경 → ADR-038

- **결정**
  - 교사 토큰·학생 기기 토큰은 `{방ID}.{무작위 32바이트}`(base64url). 서버는 무작위 부분의 SHA-256만 수업방 객체에 저장한다. 방 ID가 들어 있어 D1을 거치지 않고 바로 그 객체로 간다.
  - PIN으로 들어오면 그 기기용 교사 세션 토큰을 새로 발급한다(선생님 링크 토큰과 별개, 각각 끊을 수 있음).
  - 웹소켓은 주소에 토큰을 넣지 않고 **연결 후 첫 메시지로 인증**한다(5초 안에 안 오면 끊음). REST는 `Authorization: Bearer`.
  - 선생님 링크(`/t/{토큰}`)를 열면 토큰을 기기에 저장하고 주소창에서 즉시 지운다(`history.replaceState`). 선생님 링크 QR은 "학생에게 보이지 않게 하세요" 경고가 있는 창에서만 보인다. 설정에 `선생님 링크 새로 만들기`(이전 링크 무효).
- **이유**: 토큰이 접속 기록·방문 기록·TV 화면에 남는 길을 줄인다. 해시만 저장하므로 저장소가 새도 토큰을 되살릴 수 없다.

## ADR-020 · 보내기 묶음과 서버 저장 주기 (관문)  — **v2에서 대체됨 → ADR-046**

- **결정**
  - 학생 기기는 입력 즉시 IndexedDB에 저장하고(PRD 그대로), 서버로는 변경을 묶어 보낸다. 교사가 그 글을 서랍으로 보고 있으면 `SYNC_BATCH_OBSERVED_MS` 200ms, 아니면 `SYNC_BATCH_IDLE_MS` 1,500ms(대시보드 타일 3초 목표에 맞춘 값). 서버가 "지켜보는 중" 여부를 알려 준다.
  - 서버는 글이 바뀌면 `SERVER_PERSIST_DEBOUNCE_MS` 5,000ms(최대 대기 20,000ms) 뒤 그 글 한 행을 덮어쓴다. 연결이 끊기거나 객체가 쉬기 전에도 저장한다. (PRD 추천값 2,000ms에서 바꿈)
  - 하트비트는 `setWebSocketAutoResponse`로 객체를 깨우지 않고 답한다.
- **이유**: 웹소켓 수신 메시지를 20:1로 환산하는 규칙이 무료 한도에도 적용되는지 문서로 확인되지 않았다. 1:1로 세는 최악을 가정하면 "1초에 1메시지"는 수업 1회에 5만 건으로 일일 10만 건의 절반이다. 위 규칙이면 최악에도 수업 1회 약 2.1만 건(하트비트 제외)이라 하루 4회 수업이 들어간다(PLAN §2.6). 교사 서랍 1초·타일 3초 목표는 그대로 맞는다. 서버 저장이 몇 초 늦어도, 다시 연결될 때 Yjs가 기기 사본에서 빠진 부분을 채우므로 글은 잃지 않는다.
- **관문**: M3 부하 시험에서 Cloudflare 대시보드의 객체 요청 수를 실제로 읽어, 20:1이 적용되면 묶음 시간을 줄인다.

## ADR-021 · 시간

- **결정**: 연결·응답마다 서버 시각을 주고, 기기는 `serverNow - Date.now()` 차이로 모든 남은 시간·"몇 초 전"을 계산한다. AI 하루 한도의 하루는 `Asia/Seoul` 0시 기준. 화면 날짜도 한국 시각.
- **이유**: 학교 태블릿 시계가 틀린 경우가 흔하다(G9). Cloudflare 무료 한도는 09:00 KST에 초기화되지만 사용자에게 의미 있는 하루는 자정이다.

## ADR-022 · 데이터 규칙은 쌤유니버스에 맞춤

- **결정**
  - 이름은 snake_case, ID는 UUID, 상태값은 대문자 문자열 + CHECK (`'ACTIVE'`, `'CLOSED'`, `'DRAFT'`, `'SUBMITTED'`, `'REOPENED'`, `'PENDING'`, `'APPROVED'`, `'REJECTED'`).
  - 시각은 SQLite에 UTC 밀리초 정수로 저장하고 Postgres로 옮길 때 `timestamptz`로 바꾼다(PLAN §5에 대응표).
  - API 응답 봉투: 읽기 `{data, requestId}`, 쓰기 `{data, commandId, requestId}`, 오류 `{error:{code, message, retryable, fields}}`. 쓰기 명령은 기기가 만든 `commandId`(UUID)로 멱등.
  - 닉네임 정규화: NFKC → 앞뒤 공백 제거 → 연속 공백 하나 → 소문자. 길이 1~12자(PRD).
- **이유**: 쌤유니버스 `DB_GUIDELINES.md` D3·D6·D7, `API_CONVENTIONS.md`와 같게 해서 나중에 붙일 때 변환을 줄인다.

## ADR-023 · 장르 카탈로그 한 곳 정의

## ADR-025 · PWA 업데이트

## ADR-029 · 크게 지우면 `되살리기` 토스트

- **결정**: 한 번의 변경으로 30자 넘게 지워지면 6초짜리 토스트 "지운 글을 되살릴까요? `되살리기`". 누르면 `↶`와 같다.
- **이유**: 초3의 가장 흔한 사고가 전체 선택 후 지우기다. 시간 되감기는 `···` 안에 있어 찾기 어렵다(Antigravity 지적).

## ADR-030 · 이어 쓰기 요청 보강

- **결정**
  - 대기 중 새로고침해도 기기가 요청 번호를 기억해 기다림 화면으로 돌아간다.
  - 같은 기기의 같은 요청은 하나로 합친다. 요청은 교사가 정하거나 학생이 `취소`할 때까지 남는다(만료 없음, F-14 `[고정]` "교사가 들어오면 보인다"). 30분이 지나면 기기 쪽에만 "선생님이 아직 못 보셨어요. 조금 더 기다려요"를 더한다.
  - 요청이 2개 이상이면 대시보드 띠에 `모두 허용`이 생긴다(iPad 저장소 삭제로 여러 명이 한꺼번에 요청하는 경우, R4).
  - 서랍에 `기기 연결 끊기`: 그 학생의 기기 목록(허용 시각·마지막 사용)을 보이고 고른 기기 하나의 토큰과 연결을 끊는다(잘못 허용했을 때, `device.revoke {deviceRowId}`).
  - 학생 기기는 처음 들어올 때 `navigator.storage.persist()`를 요청한다.

## ADR-031 · 상태 관리·라우팅·움직임

- **결정**: 상태는 Zustand(PRD), 라우팅은 react-router 7(쌤유니버스와 같음), 움직임은 Motion 대신 **CSS 전환 + 작은 끌어 닫기 훅** 하나.
- **이유**: PRD 8.5의 움직임은 열기·닫기·저장 순간 150~250ms뿐이라 CSS로 충분하다. 시트 끌어 닫기만 포인터 이벤트 훅(약 80줄)으로 만든다. 첫 JS 250KB 목표에 여유가 생긴다.

## ADR-032 · 기기 저장은 직접 만든 IndexedDB 저장소

- **결정**: PRD의 `y-indexeddb` 대신 `LocalDocStore`(약 150줄)를 직접 만든다. 변경이 생길 때마다 짧은 트랜잭션 하나로 추가 기록하고, 50건마다 또는 앱을 열 때 하나로 합친다. 기기 기억(최근 수업방), 보낼 명령 줄(outbox), AI 결과도 같은 DB의 다른 저장소에 둔다.
- **이유**: `y-indexeddb` 9.0.12는 2023-11 이후 새 판이 없고, 이슈 #44(모바일 Safari에서 불러오기 실패)가 열려 있다. iPad가 주 기기라 그대로 기댈 수 없다. Safari가 긴 트랜잭션을 자동으로 닫는 문제를 피하도록 짧은 트랜잭션만 쓴다.
- **안전장치**: 기기 저장이 막힌 브라우저(사생활 보호 모드 등)는 `E_STORAGE_BLOCKED` 띠를 보이고 메모리로만 쓰되, 연결돼 있으면 서버가 원본이라 글은 남는다.
- **출처**: github.com/yjs/y-indexeddb/issues/44, registry.npmjs.org/y-indexeddb.

## ADR-033 · QR·zip 라이브러리

- **결정**: QR은 `qr`(paulmillr, SVG 출력), zip은 `fflate`(PRD 그대로).
- **이유**: PRD의 `qrcode` 1.5.4는 2024-08 이후 커밋이 없고 열린 이슈가 128개다. `qr`은 의존성이 없고 2026-09에도 새 판이 나왔다. `fflate` 0.8.3은 2026-05 새 판.
- 둘 다 쓰는 화면에서만 나중에 불러온다(첫 JS 목표).

## ADR-034 · 맞춤법 보조 엔진은 v1에서 쓰지 않음

- **결정**: 맞춤법은 LLM 하나로 한다. 무료 오픈소스 Kiwi(`kiwi-nlp`, Apache-2.0)의 띄어쓰기 교정은 MAY로 남긴다.
- **이유**: 서버에서 무료로, 약관을 지키며 쓸 수 있는 한국어 맞춤법 API를 찾지 못했다(바른 클라우드는 유료, 부산대 검사기는 개인·학생 무료로 알려져 있고 서버 API 용도가 아님, hanspell 계열은 웹 화면을 긁는 방식). Kiwi WASM은 5.4MB에 모델 파일이 따로 있어 학생 태블릿에 싣기 무겁다.

## ADR-035 · PIN 저장 두 가지  — v2에서 보강·변경 → ADR-039

- **결정**: D1에는 중복 검사와 PIN 입장용 `pin_hmac`(HMAC-SHA256, 비밀값 `PIN_HMAC_SECRET`)만, 수업방 객체에는 `pin_enc`(AES-GCM, 비밀값 `PIN_ENC_KEY`, 무작위 IV)를 둔다. `GET /api/teacher/rooms/:roomId/pin`은 교사 토큰이 있을 때만 푼다.
- **이유**: F-16 "PIN `보기`"를 선생님 링크로 들어온 다른 기기에서도 지키려면 되돌릴 수 있는 형태가 필요하다(PRD_REVIEW C13). 교사 토큰을 가진 사람은 이미 그 방 전체 권한이 있어 새로 열리는 권한이 없다. 원문 PIN은 어디에도 평문으로 남지 않는다(PRD F-20의 취지).
- **영향**: 비밀값이 하나 늘어난다(PLAN §13 비밀값 목록). 수업방이 만료되면 객체와 함께 사라진다.

## ADR-036 · LLM: 네 버튼 모두 Claude Haiku 5.5, 대체는 Claude Sonnet 5.5

## ADR-037 · 호스팅: 맥미니 자체 호스팅 + CloudFront 서울 입구

- **결정**: 쌤유 글방 서버를 쌤유니버스가 도는 맥미니에 **별도 서비스**(전용 서비스 계정, launchd 데몬, 전용 터널)로 둔다. 입구는 CloudFront 서울(무료 요금제) → Cloudflare(DNS·원본 보호) → Cloudflare Tunnel → 맥미니. 지금은 링크만으로 열리고(쌤유니버스 로그인 없음), 연동은 MAY.
- **이유 (실측, 2026-11-10, 이 맥미니 = KT)**: Cloudflare 무료 존 직접은 LAX 거점·연결 133ms·첫 응답 1.0~2.1초. CloudFront 서울 경로(쌤유니버스)는 연결 10ms·첫 응답 0.06~0.08초. 터널 연결자는 icn05·icn06. rollingthunder가 같은 경로로 웹소켓 방송 왕복 중앙값 45ms·최대 102ms를 기록했다. 무료 한도로 수업이 막히는 일이 없고, 글이 국외 저장소에 남지 않으며, 나중에 쌤유니버스와 합치기 쉽다.
- **과부하 판단**: 맥미니는 Apple M6 12코어·32GB, 측정 시 부하 약 3·메모리 여유 71%. 이 서버는 평소 CPU 1% 안팎·메모리 300MB 이하로 예상(웹소켓 30개, Yjs 업데이트 초당 수십 건). 걱정할 것은 부하보다 꼬리 지연(아바타 빌드와 겹칠 때)과 가용성이라, 데몬은 `ProcessType Interactive`로 높이고, 30+1명 시험을 아바타 빌드 중에도 돌린다.
- **가용성 위험**: FileVault 때문에 무인 재부팅 뒤 수동 잠금 해제가 필요하고, UPS가 없으며, 2026-10-06 업데이트 재부팅 뒤 Colima 문제로 1시간 45분 멈춘 기록이 있다. 대응: 컨테이너 없이 Node 프로세스 하나(ADR-039), 기기 우선 저장으로 글은 지킴, 평일 08~16시 업데이트·재부팅·배포 금지, 하트비트 감시 추가.
- **되돌릴 길**: 관문(30+1명 40분, 학교망·LTE, 재부팅 복구)을 넘지 못하면 CloudFront 서울 뒤에 Cloudflare Workers를 두는 안으로 옮긴다(`RealtimePort`·`DocStorePort`).
- **출처**: 로컬 실측(curl `/cdn-cgi/trace`, cloudflared 메트릭), `rollingthunder/wiki/decisions/입구-구조-CloudFront-터널.md`, `classlearning/docs/operations/SELFHOST_GO_LIVE.md`, docs.aws.amazon.com CloudFront flat-rate·websockets.

## ADR-038 · 실시간 서버: Hocuspocus 4

- **결정**: `@hocuspocus/server` 4.x(MIT)를 Node 프로세스 안에 둔다. 글마다 `doc:{id}`, 수업방마다 `room:{id}` 문서. 한 연결에 여러 문서를 싣는다(`HocuspocusProviderWebsocket`). 수업방 이벤트와 교사 명령은 무상태 메시지(`sendStateless`·`broadcastStateless`)로 주고받는다. 인증은 `onAuthenticate`(토큰은 주소가 아니라 연결 뒤 인증 메시지로 감), 잠금은 `connection.readOnly` 바꾸기(+ 잠금이 풀릴 때 기기의 `forceSync`), 저장은 직접 쓴 `onStoreDocument`(2,000ms/최대 10,000ms, 재시도와 내림 막기는 우리가 넣음).
- **이유**: 2026-10-28 4.8.0으로 활발하고, 필요한 기능(다중화·인증·읽기 전용·저장 지연·저장 실패 재시도)을 다 갖췄다. 직접 프로토콜(ADR-004)을 만들 이유였던 Durable Objects 구조가 사라졌다.
- **버린 대안**: `@y/websocket-server`(기능 최소), `@y/redis`(AGPL), 직접 프로토콜.
- **토큰(ADR-019 갱신)**: 무작위 128비트 이상, 서버는 해시만. 방 ID를 토큰에 넣을 필요가 없어졌다(서버 하나에서 해시로 찾음).
- **2026-11-10 실험 확인(4.8.0 소스 + Node 24.21에서 6개 실험, Claude 서브에이전트)**: `new Hocuspocus()` + `ws` noServer + 직접 `upgrade` 배선으로 Hono와 한 포트에서 동작. `connection.readOnly`는 연결 뒤에도 바꿀 수 있고 다음 메시지부터 적용(잠금 해제 뒤에는 기기의 `forceSync()` 필요). 공유 소켓에서는 `provider.attach()` 필수. 함정: 기다려 주지 않는 훅의 예외는 프로세스를 죽임 → 모든 훅 감싸기, 저장 실패는 재시도 없음 → 직접 재시도와 내림 막기, 하트비트 없음 → 웹소켓 ping과 `tick` 직접. `@hocuspocus/extension-sqlite`(better-sqlite3 12 의존)와 `@hono/node-ws`(node-server 1.x 의존)는 쓰지 않는다. 저장은 `better-sqlite3` 13.0.3 + 직접 쓴 `onStoreDocument`. 자세한 표는 PLAN §4.7.

## ADR-039 · 저장: SQLite 파일 하나

- **결정**: v1 저장소는 SQLite(WAL) 파일 하나. 전역 색인(입장 코드·PIN)과 수업방 데이터가 같은 파일에 있다. 만료 행은 지워서 "살아 있는 수업방 사이에서 유일"을 지킨다. SQL은 Postgres로 그대로 옮길 수 있게 쓴다(PRD 10.3). 백업하지 않는다.
- **이유**: 컨테이너·VM 없이 돌아 재부팅 복구가 빠르고 운영이 가볍다(쌤유니버스의 Colima 장애 기록). 이 규모(수업당 쓰기 수천 건)에 넉넉하다. 쌤유니버스 Postgres에 넣으면 그쪽 백업이 30일 보관 약속을 깬다.
- **버린 대안**: 쌤유니버스 Postgres 공유, 전용 Postgres 컨테이너.
- PIN 실패 칸(ADR-018)과 PIN 암호문(ADR-035)도 이 파일에 둔다. 지운 행은 `secure_delete`로 덮고, 만료 삭제 뒤 WAL을 체크포인트한다(PLAN §5.1).

## ADR-040 · 한글 조합 보호 (ADR-005·006 보강)

- **결정**: PRD 9.3 그대로. 통신용·편집용 Yjs 문서 둘, 반영 문 조건(조합 이벤트 닫힘 + 마지막 입력 뒤 500ms + 음절 경계 또는 2초 멈춤, 10초 보류 뒤에는 음절 경계를 빼고 300ms 멈춤으로 완화(조합 중이면 계속 기다림), 조합 고착 5초), 반영 시 상대 위치로 커서 보존, 문이 닫힌 동안 입력칸 쓰기·선택·포커스·읽기 전용 변경 금지.
- **새 근거**
  - iPad·Mac Safari는 한글 입력에 조합 이벤트를 보내지 않는다(WebKit 버그 274700, "예상된 동작"). 그래서 300ms 조건만으로는 부족하고 음절 경계 판단이 필요하다.
  - Chromium은 `value` 설정과 `setRangeText` 모두 내부에서 전체를 다시 쓴다(`setRangeText`는 선택만 보존). WebKit은 값을 바꾸면 조합을 취소한다(버그 55560). 반영 시점 통제가 핵심이다.
  - iOS 20회 반복 실측(CodeMirror 이슈 1748): textarea 0, CodeMirror 11(6.43.13에서 수정), Obsidian 7 실패.
  - CodeMirror 관리자도 지연을 견디는 동기화라면 의도적 지연이 괜찮다고 답했다(discuss.codemirror.net 6199).
- **영향**: 학생이 쓰는 도중의 교사 수정은 학생이 띄어 쓰거나 멈출 때 보인다(보통 2초, 학생이 쉬지 않고 치면 더 길 수 있음). F-18 "1초 안"은 학생이 멈춘 상태 기준으로 고쳤다(`[고정]` 한글 보호 우선).
- **차선책**: CodeMirror 6 + 같은 보류 장치(`y-codemirror.next`는 조합을 고려하지 않아 그대로는 안 됨). 지켜볼 것: Lexical `@lexical/y`(조합 중 원격 보류가 2026-10-29 병합, 아직 nightly).

## ADR-041 · 디자인: 그림책 + 글벗

- **결정**: PRD 8장. "인쇄된 그림책": 크림 종이 결, 코코아 잉크 실선, 비대칭 둥근 종이 카드, 짧고 단단한 종이 그림자. 수채 번짐은 그림 안에만(UI 위 물감 얼룩 없음). 흔들리는 손그림 선은 화면당 핵심 요소 1개에만. 버튼·칩·입력칸은 잉크 테두리와 눌리는 그림자로 또렷하게. 교사 화면은 "정돈된 출석부 90% + 종이 물성 10%". 그림은 화면당 최대 1장, 스타일 시트(선 한 굵기, 토큰 색만, 평면 채색 + 한 단계 음영)를 고정하고 글벗 캐릭터 시트 승인 뒤 나머지를 만든다. 캐릭터 기본 후보는 몽땅연필 고슴도치(학습 앱에 흔한 둥근 새를 피함).
- **Antigravity 비평 반영(2026-11-10)**: 물감 번짐 18장 제거, 손그림 테두리 범위 축소, 말풍선 꼬리 제거, 작은 크기의 표정 제거, 버튼 입체감·입력칸 초점 규칙, 대시보드 절제 기준, 그림 검수 기준.
- **이유**: 사용자 인터뷰(2026-11-10) 선택. AI 느낌을 피하려면 "그림이 많은 그림책"보다 "종이·선·물감이 분위기를 만들고 그림은 아껴 쓰는" 쪽이 안전하고, 태블릿 성능도 지킨다.
- **연결**: ADR-012(CSS Modules)·013(Base UI)·014(Phosphor Duotone)·024(대비 보정)는 그대로.

## ADR-042 · "주요 버튼 하나" 확정 (U-16 위임)

## ADR-044 · 보호자 동의 절차 없음 (U-07 답)

- **검토**: Codex(deep, 기술 검토 18건)와 Claude 서브에이전트(PRD↔PLAN 대조 32건). 모두 문서와 Hocuspocus 소스 사실에 대조해 반영했다.
- **설계를 바꾼 것**
  1. **토큰은 기기가 만든다**(256비트). 서버는 해시만 받고 토큰을 돌려주지 않는다. 이어 쓰기 허용 응답이 사라져도 기기는 이미 토큰을 알고 있고, 같은 요청을 다시 보내도 결과가 같다. 이어 쓰기의 별도 요청 비밀값은 없앴다.
  2. **제출 계약**: 기기는 쓰던 입력 기록 → 기기 저장 완료 → `unsyncedChanges == 0`을 기다린 뒤 `doc.submit {stateVector, generation}`. 서버는 자기 상태 벡터가 기기 것을 다 포함할 때만 한 트랜잭션으로 저장·스냅샷·상태를 바꾸고, 아니면 `E_SYNC_PENDING`. `다시 쓰게 하기`는 세대를 올려 늦게 온 옛 제출(`E_STALE`)을 막는다.
  3. **`저장됨`은 DB 저장 완료 뒤**: 서버가 저장 뒤 `doc.persisted {stateVector}`를 보내고, 기기는 그것이 자기 상태를 다 포함할 때만 초록으로 바꾼다.
  4. **AI 한도는 호출 전 예약**: 쿨다운·참가자·방·전체 한도를 한 SQLite 트랜잭션으로 확인하고 RESERVED 행을 넣은 뒤 호출, 끝나면 정산(우리 쪽 실패는 REFUNDED).
  5. **다듬은 글 스트림은 NDJSON**(`text`·`reset`·`done`·`error`) + 중단 신호. 제공사용 JSON 스키마는 zod에서 따로 만들고(지원하지 않는 제약 제거), 검증은 zod로.
  6. **훅 감싸기를 둘로**: 판단 훅(인증·불러오기·내림·저장)은 예외를 그대로 던지고(삼키면 인증 성공으로 처리됨), 알림 훅만 삼킨다. 웹소켓·업그레이드 `error`를 받는다(없으면 잘못된 프레임으로 프로세스 종료).
  7. **반영 문은 글 단위 조정자**: 제목·본문·메모 칸을 함께 보고, 조합 고착은 "5초 동안 활동 없음"으로(조합 시작 시각이 아니라), 커서 이동 판정은 새 입력마다 초기화, 원격 적용 전에 재진입 표시. **메모는 `Y.Text`**(같은 학생의 두 기기 동시 편집).
  8. **적용 전 검사**: 학생 업데이트를 서버 문서 사본에 먼저 적용해 길이·키·타입을 확인하고, 넘으면 그 연결을 읽기 전용으로(`E_DOC_TOO_LARGE`). 훅 안에서 바꾼 읽기 전용이 그 메시지에 바로 먹히는지는 P2-1 실험으로 확인(이전 번호 M2-1).
  9. **스키마**: 길이 같은 설정값을 SQL CHECK에서 뺌(PRD `[고정]` 설정 한 곳), 복합 외래키로 글·이어 쓰기 요청과 학생이 같은 방임을 보장, `commands`에 실행 주체·명령 이름·인자 해시(7일 보관), `ai_usage`에 예약 상태·`command_id`.
  10. **지우기·끝내기 순서**: 지우는 중 표시 → 새 작업 거부 → AI 중단·긴 조회 종료 → 연결 닫기 → 저장 예약 버림 → DB 삭제·체크포인트 → 메모리 정리(PLAN §7.7). SIGTERM은 편집을 먼저 멈춘 뒤 저장(PLAN §7.1).
  11. **운영**: 로그는 날마다 회전·7개, 릴리스마다 "새 스키마에서 이전 릴리스 시작" 시험, 백업 제외·체크포인트 성공을 운영 관문에서 확인. 시작 코드는 PRD대로 T1 안의 입력칸(별도 화면 없음), 실패는 PIN 칸으로 센다. 바뀔 수 있는 수치는 모두 PRD 12.3 키로.

## ADR-050 · 구현 순서: 위험 먼저 (2026-11-11)

- **결정**: 구현을 P0~P7 phase로 나눈다(PLAN §11). 원칙은 ① 제품을 바꿀 수 있는 위험을 먼저 확인 ② 사용자 손이 필요한 일은 일찍 부탁하고 뒤에서 흐르게 ③ 버리는 코드 없음 ④ phase마다 돌아가는 것 ⑤ 다른 에이전트 작업은 동시에 둘까지 ⑥ phase 끝에 넓은 검사 한 번.
- **바뀐 것**
  1. **실기기 한글 확인(U-10)을 약 8일째(M4)에서 약 5일째(P2 끝)로 당겼다.** 수업방·입장·디자인 없이 실제 서버 경로(Hocuspocus·SQLite·웹소켓) 위의 `/dev/editor`로 확인한다. 실패해 CodeMirror 6 차선책으로 가게 되더라도 화면을 만들기 전에 안다.
  2. **Hocuspocus 훅 안 읽기 전용 실험**(§4.7 대응 9)도 P2-1에서 한다.
  3. **P3는 P2 관문을 기다리지 않는다.** 화면은 `EditorPort`만 알아서 편집기가 바뀌어도 그대로다.
  4. 공용 핵심(M1)을 둘로 나눴다: 편집기가 쓰는 설정·오류·한글 판정은 P1, 나머지 도메인·프로토콜·문구는 P3.
  5. 캐릭터 시트를 P1에 시작한다(되풀이가 길고 코드와 무관). 평가 글(P4-18)과 처리방침(P5-3)은 앞 phase 끝무렵 미리 시작한다.
  6. Claude가 병목이라 정적 검사 도구(P1-4)와 평가 글 초안(P4-18)을 Antigravity에, 교사 화면 결합(P4-13)을 Claude 서브에이전트에 준다.
  9. **Antigravity 독립 검토 반영(같은 날, 22건)**: ① 보안 모듈(`security/*`)을 처음 쓰는 P3-3보다 앞(P2-11)으로, `store/repos/*`와 라우터 연결은 C 소유로(동시 수정 충돌) ② 개발용 글이 외래키에 막히지 않게 개발용 고정 행(`store/devSeed.ts`) ③ 빠른 터널로 열리는 `dev` 자격에 서버 시작마다 바뀌는 비밀값·`doc:dev-*` 한정 ④ 프로토콜 일부·포트·기기 저장소를 P2로 당김 ⑤ `/dev/editor`에 교사 봇·긴 글 거울 층·키보드 위 하단 바·연결 끊기를 넣어 실기기 한 번에 확인 ⑥ CloudFront 세 번째 무료 요금제를 P1~P2에 먼저 확인 ⑦ 쓰기 화면 안의 패널·시트 배치와 교사 화면의 빠진 MUST 세부를 작업에 명시 ⑧ "새 스키마에서 이전 릴리스 시작" 시험을 P3-12·P5-9에 ⑨ Anthropic 키를 U-19 때 운영·개발 두 개로 함께 받음 ⑩ P1은 P2에 필요한 것만 남기고 2일로, P3의 P4용 도메인은 P4-1로. 틀린 지적 하나(원본 비밀 머리는 서버가 아니라 Cloudflare WAF가 확인, §7.3)는 반영하지 않았다.
  7. P4에서 Claude는 제출 → AI 서버·프롬프트 → 나머지 서버 순으로 간다. 평가를 일찍 돌려 사용자 승인(U-11·U-01)을 기다리는 동안 다른 일을 한다.
  8. 학교 와이파이에서 v0 주소를 한 번 열어 보는 선택 단계(P3-16)를 두었다. 웹소켓 차단을 리허설보다 일찍 안다.
- **개발 전용 자격**: P2의 `/dev/editor`는 `dev` 자격으로 글 문서에 붙는다. `DEV_DOCS_ENABLED=true`이고 운영이 아닐 때만 받으며, 운영에서 켜져 있으면 서버가 시작을 거부한다. 운영 빌드에는 `/dev/*` 화면이 없다(`bundle.mjs` 검사). 실기기 시험은 Cloudflare 빠른 터널로 시험하는 동안만 연다.
- **버린 대안**: 이전 순서(M0 → M1 → M2·M3 → M4 관문). 한글 위험을 화면·그림·배포를 다 만든 뒤에 알게 된다. / 편집기 화면을 서버 없이 같은 페이지 안의 가짜 상대로만 시험: 실제 소켓·재연결·지연이 빠져 실기기 확인의 의미가 줄어든다.
- **되돌리기**: phase는 작업 묶음일 뿐이라 순서만 바꾸면 된다. 이전 번호와의 대응은 PLAN §11.10.
